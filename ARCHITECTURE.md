# 📑 Архитектурный манифест проекта SmartGate (MVP)

## 1. Концепция и Имя проекта
* Имя проекта: SmartGate (Альтернативное кодовое имя: BorderBoy).
* Концепция: Селф-хостед (self-hosted) умный шлюз для автоматизации сплит-маршрутизации домашнего/офисного трафика в условиях жестких DPI-блокировок в РФ. 
* Философия: Максимально дружелюбный для пользователя процесс установки ("всё управление из одной точки") при сохранении под капотом профессиональной, масштабируемой сетевой архитектуры операторского уровня.

---

## 2. Инженерные предпосылки и эволюция Data Plane
Архитектура SmartGate опирается на глубокий анализ устойчивости протоколов связи к современным системам фильтрации трафика (ТСПУ/DPI):
1. OpenVPN — полностью блокируется DPI по характерным сигнатурам хендшейка.
2. IPsec (IKEv2/L2TP) — блокируется операторами связи ковровым методом по протоколам ESP/AH и UDP-портам 500/4500.
3. OpenSSH (sshtun) — выбран нами как наиболее стабильное, проверенное временем базовое решение. Оно обеспечивает честный L3-туннель (tun-интерфейсы) и нативную интеграцию с динамическим роутингом.

Наше стратегическое решение: Чтобы защитить sshtun от будущих эвристических блокировок (анализ паттернов трафика и мелких пакетов BGP/OSPF), мы закладываем в Data Plane "сэндвич"-модель: SSH-сессия принудительно оборачивается в слой обфускации Shadowsocks-rust. Это превращает весь сетевой поток в неразличимый TLS-подобный криптографический шум на 443 порту.

## 3. Терминология и Топология сети (Glossary)

Для исключения путаницы в кодовой базе и конфигурационных файлах мы утвердили следующие англоязычные термины:

* Upstream Node (или Upstream) — удаленный сервер за рубежом (например, vpn.dfkj.ru). Выступает в роли Route Server — генерирует префиксы и анонсирует их вниз.
* Gateway Node (или Gateway) — домашний или офисный шлюз в РФ (ru1.dfkj.ru, tower.dfkj.ru). Принимает анонсы, является главной точкой управления и пультом для всей системы.
* Route Injector — асинхронный модуль на Upstream Node, который скачивает списки IP через JSON API и заносит их в FRR.
* Gateway Supervisor — демон на домашнем шлюзе, контролирующий выживаемость процессов Shadowsocks, SSH и интерфейсов tun.

## 4. Сетевой стек: eBGP внутри VRF

Вместо использования устаревших для таких задач OSPF или iBGP, наш проект полностью переходит на рельсы eBGP (External Border Gateway Protocol) в связке с Linux VRF:

* Масштабируемость: OSPF деградирует на списках в 48 000+ маршрутов из-за постоянного математического пересчета графа SPF при мигании линков. BGP создан для миллионов префиксов и работает на базе надежного TCP (порт 179).
* Автоматический Best Path Selection: Каждому узлу мы присваиваем свою Private ASN (например, Upstream — 65000, домашний Gateway — 65001, резервный сосед — 65002). Домашний шлюз видит маршруты из нескольких источников и автоматически выбирает лучший путь на основе длины AS-Path. При падении прямого туннеля переключение на соседа происходит мгновенно и без шторма апдейтов.
* Изоляция таблиц через VRF: Чтобы тысячи blackhole-маршрутов на Upstream не засоряли ядро ОС и не ломали интернет самому серверу, мы складываем их в изолированную таблицу маршрутизации Linux — vrf-export.

## 5. Точка входа и UX установки (All-in-One Gateway Script)

Мы отказываемся от сложной ручной настройки серверов и прыжков по консолям. Домашний шлюз становится единой точкой развертывания.

[ Пользователь ] ---> (Запуск install.sh одной командой) ---> [ Gateway Node (Дом) ]
                                                                      |
                                             (Автоматическая настройка по SSH)
                                                                      v
                                                            [ Upstream Node (Европа) ]

Сценарий развертывания:
1. Пользователь заходит на домашний Gateway Node и запускает скрипт-однострочник.
2. Прямо в консоли шлюза (или через локальный Web UI) пользователь вводит IP и root-пароль своей чистой зарубежной VPS (Upstream Node).
3. Домашний шлюз сам подключается к VPS по SSH и выполняет всю грязную работу:
   - Устанавливает Docker (если его нет).
   - Создает в ядре VPS сетевой vrf-export.
   - Запускает Docker-контейнер smartgate-upstream (внутри упакованы FRR с gRPC API и Shadowsocks-сервер).
   - Прописывает публичный SSH-ключ шлюза в authorized_keys на VPS для работы sshtun.
4. Шлюз возвращается в локальный контекст, запускает домашний контейнер smartgate-gateway, поднимает обфусцированный sshtun и включает eBGP. Сеть работает.

## 6. Технологический стек MVP

* CLI / Установщик / Бэкенд управления: Go (Golang) или Python (FastAPI + Paramiko). Go предпочтителен для CLI-бинарника (нет зависимостей, один файл), Python — для высокой скорости прототипирования Control Plane.
* Сетевой движок (Data Plane): Docker-контейнеры с флагом --privileged --net=host. Внутри контейнеров: FRR (с включенным bgpd и staticd) и shadowsocks-rust.
* FRR Взаимодействие: Использование встроенного FRR gRPC API (Northbound/YANG) для атомарного и транзакционного добавления маршрутов без парсинга текстовых конфигов.
