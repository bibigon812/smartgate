# 📑 Архитектурный манифест проекта SmartGate (MVP)

## 1. Концепция и Имя проекта
* Имя проекта: SmartGate (Альтернативное кодовое имя: BorderBoy).
* Концепция: Селф-хостед (self-hosted) умный шлюз для автоматизации сплит-маршрутизации домашнего/офисного трафика в условиях жестких DPI-блокировок в РФ. 
* Философия: Максимально дружелюбный для пользователя процесс установки ("всё управление из одной точки") при сохранении под капотом профессиональной, масштабируемой сетевой архитектуры операторского уровня.

---

## 2. Инженерные предпосылки и эволюция Data Plane
Архитектура SmartGate опирается на глубокий анализ устойчивости протоколов связи к современным системам фильтрации трафика (ТСПУ/DPI):
1. OpenVPN — полностью блокируется DPI по характерным сигнатурам хендшейка.
2. IPsec (IKEv2/L2TP) — блокируется операторами связи ковровым методом по протоколам ESP/AH и UDP-портам 500/4500.
3. OpenSSH (sshtun) — выбран нами как наиболее стабильное, проверенное временем базовое решение. Оно обеспечивает честный L3-тунлель (tun-интерфейсы) и нативную интеграцию с динамическим роутингом.

Наше стратегическое решение: Чтобы защитить sshtun от будущих эвристических блокировок (анализ паттернов трафика и мелких пакетов BGP/OSPF), мы закладываем в Data Plane "сэндвич"-модель: SSH-сессия принудительно оборачивается в слой обфускации Shadowsocks-rust. Это превращает весь сетевой поток в неразличимый TLS-подобный криптографический шум на 443 порту.

## 3. Терминология и Ролевая модель (Glossary)

Для исключения путаницы в кодовой базе и конфигурационных файлах мы утвердили следующие англоязычные термины:

* Upstream Node (или Upstream) — удаленный сервер за рубежом (например, vpn.dfkj.ru). Выступает в роли центрального хаба и Route Server — генерирует префиксы и анонсирует их вниз. Обладает статическим белым IP.
* Gateway Node (или Gateway) — клиентский шлюз (домашний сервер tower, резервный хост box01, либо промежуточная VPS в РФ ru1 для подключения мобильных устройств). Находится за NAT или брандмауэром провайдера.
* Route Injector — асинхронный модуль на Upstream Node, который скачивает списки IP через JSON API и заносит их в FRR.
* Gateway Supervisor — демон на каждом шлюзе, контролирующий выживаемость процессов Shadowsocks, SSH и локальных интерфейсов tun.

## 4. Сетевая топология: Multi-Gateway Звезда (Hub-and-Spoke)

Система поддерживает одновременное подключение множества Gateway-узлов к одному центральному Upstream-серверу. Инициатором туннеля всегда выступает Gateway Node (снизу вверх), что решает проблему "серых" IP-адресов и NAT домашнего региона.

Передача маршрутов осуществляется по eBGP (External Border Gateway Protocol) внутри изолированных Linux VRF:

* Выделение ASN: Каждому участнику сети присваивается своя Private ASN. Например: Upstream Node — 65000, Домашний шлюз — 65001, Мобильный хаб в РФ — 65002.
* Автоматический Best Path Selection: Gateway Node видит маршруты из разных источников (напрямую от Upstream или транзитом через соседний Gateway) и автоматически выбирает лучший путь на основе длины AS-Path. При падении прямого туннеля переключение на соседа происходит мгновенно на уровне алгоритма BGP Best Path без нагрузки на процессор.
* Изоляция таблиц на Upstream: Чтобы тысячи blackhole-маршрутов не засоряли основное ядро ОС и не ломали интернет самому зарубежному серверу, они складываются в изолированную таблицу маршрутизации Linux — vrf-export.
* Динамические соседи: FRR на Upstream настраивается через Peer Groups и Listen Range для автоматического приема eBGP-соседства от легитимных гейтвеев без ручной правки конфигов при добавлении новых точек.

## 5. Точка входа и UX установки (All-in-One Gateway Script)

Мы отказываемся от сложной ручной настройки серверов и прыжков по консолям разных машин. Один из Gateway-узлов (например, домашний ПК) становится единым пультом управления.

[ Пользователь ] ---> (Запуск install.sh одной командой) ---> [ Центральный Gateway ]
                                                                      |
                                             (Автоматическая настройка по SSH)
                                                                      v
                                                    [ Upstream Node и другие Gateways ]

Сценарий развертывания:
1. Пользователь запускает скрипт-установщик на своем основном Gateway.
2. В консоли (или через локальный Web UI) вводятся IP и root-пароли чистой зарубежной VPS (Upstream) и, при необходимости, дополнительных промежуточных VPS в РФ.
3. Центральный Gateway сам подключается к удаленным серверам по SSH и выполняет за пользователя всю грязную работу:
   - Устанавливает Docker (если его нет).
   - Создает в ядре Upstream сетевой vrf-export.
   - Запускает Docker-контейнеры smartgate-upstream и smartgate-gateway на соответствующих узлах.
   - Прописывает публичные SSH-ключи для беспарольной работы sshtun.
4. Все узлы запускают свои локальные "сэндвич"-туннели (SSH over Shadowsocks) в сторону Upstream и мгновенно объединяются в eBGP звезду.

## 6. Технологический стек MVP

* CLI / Установщик / Бэкенд управления: Go (Golang) или Python (FastAPI + Paramiko). Go предпочтителен для CLI-бинарника (нет зависимостей, один файл), Python — для высокой скорости прототипирования Control Plane.
* Сетевой движок (Data Plane): Docker-контейнеры с флагом --privileged --net=host. Внутри контейнеров: FRR (с включенным bgpd и staticd) и shadowsocks-rust.
* FRR Взаимодействие: Использование встроенного FRR gRPC API (Northbound/YANG) для атомарного и транзакционного добавления маршрутов без парсинга текстовых конфигов.
